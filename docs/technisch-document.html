1. Doelstelling

Clausula is een webapplicatie waarmee familierechtmediators geüploade juridische documenten — ouderschapsplannen, convenanten en huwelijkse voorwaarden — automatisch laten screenen op juridische volledigheid, juridische juistheid, balans, interne conflicten en taalkundige kwaliteit.

De app analyseert documenten via de Anthropic Claude API, streamt resultaten progressief naar de browser (SSE), en toont bevindingen als gefilterde issuekaarten per dimensie. Bij meerdere documenten (OP + Convenant) vindt er een aanvullende cross-document verificatie plaats.

Naast screening biedt de app dossierbeheer (meerdere versies per dossier), conceptgeneratie van clausules via Claude, en PDF-rapportage.

4.2 Pseudonimisering

Vóór verzending naar de server vervangt de browser alle persoonsgegevens door fictieve equivalenten. Dit gebeurt via een deterministisch bouwAnonMap(classificatie)-algoritme dat een bidirectionele vertaalkaart opbouwt.

flowchart LR
  A["Echte namen\n(classificatie)"] -->|"bouwAnonMap()"| B["naarAnon-map\n(echt → pseudo)"]
  B -->|"anonimiseerTekst()"| C["Gepseudonimiseerd\ndocument"]
  C -->|"→ Claude API"| D["Claude-output\n(pseudoniemen)"]
  D -->|"herstelAnonObj()"| E["Herstelde output\n(echte namen)"]
  B -.->|"inverse"| F["naarEcht-map\n(pseudo → echt)"]
  F --> E
Naamcomponent-mapping Voornaam-pseudoniem (bijv. "Thomas") herstelt naar de volledige echte naam. Achternaam-pseudoniem (bijv. "Bergman") herstelt naar alleen de echte achternaam. Dit voorkomt het samenvoegen van een verkorte voornaam uit een bankrekening met de volledige naam na herstel.

4.3 Cross-document verificatie

Als er 2+ hoofddocumenten zijn (bijv. OP + Convenant), voert de server ná de per-document analyse een derde Claude-call uit die beide documenten naast elkaar legt. Cross-doc issues krijgen een stabiele gedeelde cross_doc_id zodat afhandeling in één document gesynchroniseerd wordt met het andere.

flowchart TD
  A["Per-doc analyse\n(OP)"] & B["Per-doc analyse\n(Convenant)"] --> C["Cross-doc call\n(beide docs tegelijk)"]
  C --> D["Issues met cross_doc_id"]
  D --> E["Sync via syncCrossDocIssue()"]
  E --> F["OP-panel"] & G["Convenant-panel"]
Dimensie-beperking cross-doc Cross-doc issues mogen uitsluitend de dimensies juridisch, volledigheid of balans krijgen — nooit conflicten of grammatica. Die zijn gereserveerd voor intra-document bevindingen.

7. Privacy & beveiliging

Pseudonimisering vóór AI
Client-side, in browser
Echte namen en IBAN-nummers verlaten de browser nooit onverwerkt. Claude-output bevat uitsluitend pseudoniemen die direct na ontvangst worden hersteld.
Namen-versleuteling in Supabase
AES-256-GCM, server-side sleutel
namen_map (de vertaalkaart pseudoniem→echt) wordt versleuteld opgeslagen. De sleutel (NAAM_ENCRYPTION_KEY) staat uitsluitend in de Vercel-omgeving.
Supabase RLS
Row-level security per org_id
Elke rij in screeningen is gebonden aan een org_id. Gebruikers van kantoor A kunnen nooit data van kantoor B zien, ook niet via directe API-aanroepen.
Service role key
Uitsluitend server-side
De SUPABASE_SERVICE_ROLE_KEY staat nooit in de client-bundle. De browser gebruikt uitsluitend een Supabase JWT (via magic link / sessie).

Rechten van betrokkenen (AVG art. 15–22)

De betrokkenen zijn de scheidende partijen (niet de mediator). Zij hebben zelf geen account in het systeem — de mediator verwerkt hun data namens hen. Dit maakt de mediator tot verwerkingsverantwoordelijke en het kantoor tot aanspreekpunt voor rechtenverzoeken.

RechtStatusToelichting
Inzage (art. 15)IndirectMediator kan screeningen en PDF-rapport exporteren en aan betrokkene tonen. Geen selfservice-portal voor betrokkenen.
Verwijdering (art. 17)OndersteundVia de UI kan een mediator een screening verwijderen; Storage-cleanup verwijdert ook de bijbehorende PDFs. Betrokkene moet dit via de mediator aanvragen.
Rectificatie (art. 16)Niet geïmplementeerdNamen kunnen niet gecorrigeerd worden zonder de analyse opnieuw te draaien. Workaround: screening verwijderen en opnieuw analyseren.
Dataportabiliteit (art. 20)GedeeltelijkPDF-rapport exporteerbaar via window.print(). Geen machine-readable export (JSON/CSV) van de ruwe analysedata.
Bezwaar (art. 21)IndirectVia verwijdering van de screening. Geen expliciete bezwaar-workflow.

8. Design beslissingen

Één index.html, geen framework
Gekozen boven React / Vue
Geen build-stap, directe Vercel-deploy, minimale afhankelijkheden. Trade-off: minder DX bij schaalbaarheid, maar voor een single-team product ruimschoots voldoende.
Tool-use voor JSON-output
Verplichte tool-aanroep
Claude's tool-use geeft gevalideerde JSON zonder parse-fouten. Alternatief (JSON in tekstblok) vereist fragiele regex-extractie en faalt bij lange outputs.
2 parallelle calls per document
Structuur (call 1) + Bevindingen (call 2)
Vroeger 3 calls (juridisch + balans + consolidatie). Samenvoeging tot 2 calls vermindert latency en elimineert cross-call deduplicatie. Claude ziet de volledige context in één run.
SSE voor progressieve weergave
Server-Sent Events boven polling
Resultaten worden direct na binnenkomst gerenderd. De gebruiker ziet al issues verschijnen terwijl andere dimensies nog analyseren. Polling zou merkbaar vertraagd aanvoelen.
Cross-doc als aparte third call
Dedicated micro-call
Andere documenten meegeven als context in de per-doc calls veroorzaakte cross-document "besmetting" (issues van OP in Convenant en vice versa). Dedicated call met uitsluitend cross-doc instructies is betrouwbaarder.
Versioning in dossier
versie_nr + versie_label per screening
Mediators werken iteratief: document gaat heen en weer. Elke analyse-ronde slaat een nieuwe versie op zodat de voortgang over tijd zichtbaar is.
Conf+ = conflicten ∪ cross_doc
Samengevoegd in dossier-overzicht
In de dossier-cirkelweergave tellen cross-doc issues mee in de "Conflicten"-cirkel. In de analyse-detailweergave blijft cross-doc een aparte chip voor gefilterde navigatie.
PDF-rapport via window.print()
Browser-print boven server-side rendering
Geen extra server-component nodig. Nadeel: opmaak beperkt tot wat browsers afdrukken. Toekomstig alternatief: Gotenberg op EU-VPS voor AVG-conforme server-side PDF-generatie.
IndexedDB voor DOCX-cache
Browser-lokaal, geen server betrokken
Adobe-geconverteerde DOCX-blobs worden opgeslagen in IndexedDB (key: screeningId:docType). Hierdoor is de Word-export beschikbaar zonder heranalyse of herconversie. AVG-conform: geen persoonsdata verlaat de browser. Valt weg bij tab sluiten of browser-schoon; fallback: tekst-DOCX via maakDocxVanTekst().

NAAM_ENCRYPTION_KEY gecompromitteerd Key onmiddellijk roteren in Vercel. Alle bestaande namen_map-records zijn met de oude key versleuteld — deze zijn na rotatie niet meer te ontsleutelen. Alle screeningen opnieuw verwerken of namen_map wissen. Dit is een kritiek scenario — overweeg key-rotatieprocedure vooraf te documenteren.
Geen geautomatiseerde monitoring Er zijn geen uptime-monitors, error-rate-alerts of kosten-alerts geconfigureerd. Aanbevolen minimale set: Vercel-foutmelding via e-mail (ingebouwd), Anthropic spend-limiet instellen in API-dashboard, Supabase database-size-alert.

11. Skills-documentatiesysteem

Clausula gebruikt een skill-systeem in .claude/skills/ voor het vastleggen van niet-voor-de-hand-liggende technische kennis die niet direct uit de code af te lezen is. Skills worden geladen door Claude Code wanneer een taak raakt aan het onderwerp van de skill (op basis van de description in de frontmatter).

Doel Skills zijn de overdrachtslaag tussen sessies. Ze voorkomen dat designbeslissingen, veldnaamconventies, valkuilen en architectuurkeuzes opnieuw uitgelegd moeten worden bij elke nieuwe Claude-sessie.
